# FitTrack

[![Android build](https://github.com/thisisarindam/fittrack-android/actions/workflows/android-build.yml/badge.svg)](https://github.com/thisisarindam/fittrack-android/actions/workflows/android-build.yml)

FitTrack is a local-first fitness tracking app built around a simple, repeatable full-body training plan. It is designed to help someone follow a structured workout schedule, log progress exercise by exercise, and keep track of completed sessions without needing a backend service or a complicated app setup.

At a high level, this repo combines:
- a Next.js web app for the workout experience
- a mobile wrapper for Android via Capacitor
- a static exercise catalog and weekly training plan
- local browser storage for workouts, logs, and history

This makes the project feel like a lightweight personal training dashboard that can run in the browser and also be packaged as an Android app.

## What the app is about

The app focuses on a Monday / Wednesday / Saturday full-body strength routine designed for fat loss and general conditioning. Each workout day includes a curated set of exercises, sets, rest times, and simple coaching cues.

The core workflow is:
1. Open the app and see the next scheduled workout
2. Start a workout session for that day
3. Work through each exercise one at a time
4. Log sets, weights, reps, and notes as you go
5. Resume or review previous sessions from history

The plan is intentionally practical and easy to follow: the app is not trying to be a huge gym platform. It is a focused training companion for a repeatable program.

## Features at a glance

- 💪 Weekly full-body schedule with Monday, Wednesday, and Saturday sessions
- 🏋️ Exercise-by-exercise logging for strength and conditioning work
- 📈 Workout tracking with saved progress and unfinished sessions
- 🕘 History page for completed and in-progress workouts
- 🧠 Exercise catalog with names, images, target muscles, and movement cues
- 🔒 Local-first data storage in the browser (no user accounts or backend required)
- 📱 Android packaging using Capacitor so the same app can run as a mobile app

## How the workout logic works

The app keeps a static training plan in the application code. The plan is defined in the exercise catalog and weekly schedule, and it includes:
- exercise names and images
- rest periods and rep targets
- movement cues and muscle groups
- Monday / Wednesday / Saturday workout rotation

Workout session data is stored in browser storage so a user can continue a session later or review old workouts. The app reads saved session data and updates progress dynamically without needing a remote database.

## Android app setup

This repo includes an Android project under the `android/` folder, so the same app can be wrapped as a native Android app with Capacitor.

### Download APK

The latest Android build is produced by the GitHub Actions workflow in this repo. Download it from the workflow page and install it on your device.

1. Open the latest workflow run from the badge above.
2. Download the generated `fittrack-debug-apk` artifact.
3. On your Android device, install the APK file.
4. If Android blocks installation, enable “Install unknown apps” for your browser or file manager.

### Build locally

Build the web app first, then sync it with the Android project:

```bash
npm run build
npx cap sync android
```

To open the Android project in Android Studio:

```bash
cd android
./gradlew assembleDebug
```

You can also run the Android project from Android Studio or use the Capacitor CLI commands for local Android development.

## Why this repo exists

This project is built for a simple use case: helping someone consistently train with a fixed routine while keeping the app light, portable, and easy to maintain. Instead of building a full backend-driven fitness platform, it focuses on the essentials:
- a clear training plan
- fast session logging
- saved progress
- history and review
- mobile-friendly access

If someone looks at this repository, they should understand it as a personal fitness tracking app centered around a structured workout plan and local workout history.

## Notes

This project is intentionally local-first and browser-based. That means user data is saved on the device where the app is running, which is ideal for a personal training tool without needing authentication or server infrastructure.
